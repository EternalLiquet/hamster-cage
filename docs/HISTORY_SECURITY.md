# History Security Pass (#28)

Scope: daily history, explanations and confirmed append-only corrections (#25–27). Newly collected data, permissions, Android components, network surface, credentials and secrets: **none**. This pass adds display validation and failure handling, with synthetic regression fixtures. Existing manual/correction IDs, bounds, timestamps and optional private notes remain app-private Room source facts. No new schema, export or shared-storage file is introduced.

## Trust boundaries and repaired findings

Manual dates, notes, office choices and correction targets cross UI parsing, frozen engine preview and repository validation before an explicit confirmation appends a record. The repository rejects unknown targets/offices, excessive notes, invalid/future/sub-millisecond bounds, conflicting IDs and invalid append ordering. Bound SQL parameters store note content literally. A malicious SQL-like note cannot rewrite raw observations. Exact retries are idempotent; rejected mutations leave every source collection unchanged. Existing independent #27 evidence covers stale source/policy rejection, serialized policy changes, restart/migration and append-only revert.

Audit IDs were displayed without control-character sanitation. IDs now use visible code-point escapes for non-identifier characters, including literal backslashes, so distinct IDs cannot collapse to the same label when controls are removed. Long labels include a full SHA-256 suffix; reserved display markers are themselves escaped. This bounds single-line output without editing stored values. Collision regressions cover control versus literal-escape IDs, empty values and differing truncated suffixes. Names and notes already use bounded literal Compose Text with no markup interpretation. A corrupt/exhausted maximum correction sequence previously raised arithmetic overflow during preview; it now produces a static error and offers cancellation, with no confirmation or write. These fixes do not discard corrupt evidence.

Private notes are intentionally visible when their history detail is opened, and timestamps/source IDs are intentional audit fields. Screenshots or the app switcher can contain that visible attendance information; no screenshot-blocking claim is made. Exact office coordinates are absent from detail. Preview alone and Cancel do not write. There is no destructive history action in this slice; separately reviewed privacy deletion belongs to #31. Denied location does not gate editing. No credential/network dependency exists. Failed saves retain an editable draft and show a sanitized message; unsupported/corrupt storage remains unavailable without reset or sensitive diagnostic details.
