# Departure estimate contract (#23)

`AttendanceEngine.departure` returns an explicitly named Today, Week through today, Full week, Rolling 30 days or Rolling 90 days target. It uses that window's current denominator and unioned accrued credit, including previous visits. The full-week option includes projected requirements; the other windows end today.

An unambiguous eligible open session begins accruing only after its uncredited arrival walking grace expires, then continues at one credited minute per elapsed minute. During that initial window, the projection must account for the remaining delay before any further credited minute. The credited target instant is distinct from the estimated raw/geofence exit instant, which subtracts that office's exit/departure grace and never precedes now. Exit grace can permit a projected departure before the credited target instant; it never adds accrued attendance to the dashboard or history. Neither timestamp creates a source fact.

Missing coverage suppresses estimates for the longer windows. Relevant malformed, repeated, stale or missing boundaries, unresolved invalid input and multiple eligible open offices require review, even when provisional credit appears sufficient. A benign duplicate observation does not suppress the estimate. A clean already-satisfied target requests zero additional time and has no predicted exit timestamp. Without an open eligible session, an unmet target has no exit prediction.

For **Today**, missing history before the current policy-local date does not suppress a useful estimate. Calculate the daily target from today's known and provisional credited intervals plus the single eligible open session. Do not require a known week, 30-day or 90-day balance, or turn pre-install days into zero attendance. Those longer windows may remain Unknown while Today displays a leave-at time. Limit review blocking to sessions or source facts affecting today's policy-local window: a dated prior-day orphan correction or invalid observation cannot suppress a clean Today projection. Current-day anomalies and source facts whose date cannot be established remain fail-closed. Today's incomplete coverage remains a visible caveat; a specific current-day ambiguity, unhealthy/stale session, missing target or impossible time boundary still prevents a confident projection. Name the reason and next action rather than using the generic “History incomplete” message for Today.

The Today leave-at time identifies the projected geofence EXIT, the daily target it satisfies and whether the session or coverage is provisional. An unmet target advances from the evaluation instant, first accounting for any remaining uncredited arrival grace, then the remaining credited minutes; exit/departure grace affects only the projected EXIT and cannot put it before now. Already-earned totals stop at the evaluation instant. If today's target is already met, say “Goal met. You can leave now” instead of showing a past timestamp; while today is not fully tracked, detection is unconfirmed or a departure awaits confirmation, the Today text stays an explicit estimate (see [Dashboard](DASHBOARD.md)). If no eligible session is open, the target is missing, timestamps are contradictory, eligible sessions overlap ambiguously or a review state cannot be resolved, show the specific actionable reason without a falsely precise time. Distinguish future clock events, stale sessions, conflicting entry/exit bounds, unresolved corrections or manual bounds, unknown offices and an unreachable day/session horizon so the user knows whether to check the clock, review History, inspect office setup or adjust the target.

A projection cannot borrow credit beyond the selected window or continue past the policy's safe open-session duration. Full-week projections can cross midnight where both bounds allow it. Calculations use elapsed instants and policy-local date boundaries, including DST, rather than assuming 24 hours per date. Tracking health remains an additional UI integration gate in #19/#22; this pure estimator cannot infer permission or geofence delivery health.

The #23 focused tests cover the five named targets, met/unmet targets, prior credit, unioned overlaps, independent grace, leave-now behavior, holidays/WFH, rolling and weekly boundaries, missing history, anomalies before apparent satisfaction, correction resolution, midnight and DST. Issue #80 additionally requires a fresh-install/no-history Today case, independent Unknown rolling windows, prior-day orphan/invalid isolation versus current-day or undatable fail-closed review, session refresh/restart, both zero and nonzero grace settings, cross-midnight and actionable unavailable states, plus a running-app small-screen check. Synthetic Room/DataStore activity recreation and a synthetic real-process restart can establish persisted-state recomputation; neither establishes physical geofence delivery. These #80 checks are acceptance requirements, not independent completion evidence. Actual geofence behavior remains separate; no phone checks are claimed here.

## Qualified Today estimates (#133)

An unchanged review save used to be the only way to see a leave time after an ordinary lunch break. The editor appends a correction with whole-minute bounds; the engine then treats the visit as MANUAL and drops its review, which removed the block. The save was a correction, not a confirmation, and it nudged credit by its truncation.

Today now projects through two kinds of boundary doubt that can only make the estimate later than necessary, and names them in `DepartureEstimate.assumptions`:

- `EARLIER_EXIT_UNCONFIRMED`: an earlier, uncorrected visit today ends at an observed-time geofence EXIT that was never confirmed (for example, its five-minute verification window expired without samples, which the repository records as uncertain and also lists as "delayed"). Credit already stops at that EXIT, so if the user actually stayed, the true leave time is earlier. A receipt-timed EXIT can be later than the departure and still requires review.
- `STILL_PRESENT_WHILE_EXIT_CHECKED`: the current visit has a candidate EXIT still being verified. Credit stays capped at the candidate; the projection assumes continued presence. Another office's arrival during the visit is a contradiction and still blocks.

Neither assumption changes credited time, confidence or review reasons, and neither writes a correction. A reverted correction restores the visit's qualification. A restored visit holding a candidate or rejected EXIT does not qualify, because those credit caps skip any session carrying a correction ID. The sessions stay LOW and listed in History, where a deliberate correction remains an explicit, audited MANUAL change. Later evidence or the verification deadline settles a candidate on replay. A bare EXIT before the day's first credible visit (for example, overnight re-registration noise) is no longer blocking just because the later visit is closed or awaiting a check. A missing ENTER with no later visit, an unconfirmed gap inside attendance, a stale visit, conflicting offices and other current-day anomalies still block. `nonBlockingSessionIds` lists the sessions set aside this way.

Entry grace is the walk from the geofence to the badge scanner. It applies once per genuine arrival, including a return from lunch, and duplicate or bounced ENTERs do not restart it. Exit grace only moves the projected EXIT earlier than the credited target; it never reduces or adds credit. In the #133 fixture, the raw visits come to 293.70 minutes at evaluation. The candidate EXIT caps the open visit, leaving 290.46 observed minutes. The two office-2 entry graces (5 minutes each) leave 280.46 credited minutes. Exit grace, short-gap reconciliation (the 62-minute lunch gap exceeds 10 minutes), unknown coverage and the historical corrections contribute nothing to the difference.
