# Departure estimate contract (#23)

`AttendanceEngine.departure` returns an explicitly named Today, Week through today, Full week, Rolling 30 days or Rolling 90 days target. It uses that window's current denominator and unioned accrued credit, including previous visits. The full-week option includes projected requirements; the other windows end today.

An unambiguous eligible open session begins accruing only after its uncredited arrival walking grace expires, then continues at one credited minute per elapsed minute. During that initial window, the projection must account for the remaining delay before any further credited minute. The credited target instant is distinct from the estimated raw/geofence exit instant, which subtracts that office's exit/departure grace and never precedes now. Exit grace can permit a projected departure before the credited target instant; it never adds accrued attendance to the dashboard or history. Neither timestamp creates a source fact.

Missing coverage suppresses estimates for the longer windows. Relevant malformed, repeated, stale or missing boundaries, unresolved invalid input and multiple eligible open offices require review, even when provisional credit appears sufficient. A benign duplicate observation does not suppress the estimate. A clean already-satisfied target requests zero additional time and has no predicted exit timestamp. Without an open eligible session, an unmet target has no exit prediction.

For **Today**, missing history before the current policy-local date does not suppress a useful estimate. Calculate the daily target from today's known and provisional credited intervals plus the single eligible open session. Do not require a known week, 30-day or 90-day balance, or turn pre-install days into zero attendance. Those longer windows may remain Unknown while Today displays a leave-at time. Limit review blocking to sessions or source facts affecting today's policy-local window: a dated prior-day orphan correction or invalid observation cannot suppress a clean Today projection. Current-day anomalies and source facts whose date cannot be established remain fail-closed. Today's incomplete coverage remains a visible caveat; a specific current-day ambiguity, unhealthy/stale session, missing target or impossible time boundary still prevents a confident projection. Name the reason and next action rather than using the generic “History incomplete” message for Today.

The Today leave-at time identifies the projected geofence EXIT, the daily target it satisfies and whether the session or coverage is provisional. An unmet target advances from the evaluation instant, first accounting for any remaining uncredited arrival grace, then the remaining credited minutes; exit/departure grace affects only the projected EXIT and cannot put it before now. Already-earned totals stop at the evaluation instant. If today's target is already met, say “You can leave now” instead of showing a past timestamp. If no eligible session is open, the target is missing, timestamps are contradictory, eligible sessions overlap ambiguously or a review state cannot be resolved, show the specific actionable reason without a falsely precise time. Distinguish future clock events, stale sessions, conflicting entry/exit bounds, unresolved corrections or manual bounds, unknown offices and an unreachable day/session horizon so the user knows whether to check the clock, review History, inspect office setup or adjust the target.

A projection cannot borrow credit beyond the selected window or continue past the policy's safe open-session duration. Full-week projections can cross midnight where both bounds allow it. Calculations use elapsed instants and policy-local date boundaries, including DST, rather than assuming 24 hours per date. Tracking health remains an additional UI integration gate in #19/#22; this pure estimator cannot infer permission or geofence delivery health.

The #23 focused tests cover the five named targets, met/unmet targets, prior credit, unioned overlaps, independent grace, leave-now behavior, holidays/WFH, rolling and weekly boundaries, missing history, anomalies before apparent satisfaction, correction resolution, midnight and DST. Issue #80 additionally requires a fresh-install/no-history Today case, independent Unknown rolling windows, prior-day orphan/invalid isolation versus current-day or undatable fail-closed review, session refresh/restart, both zero and nonzero grace settings, cross-midnight and actionable unavailable states, plus a running-app small-screen check. Synthetic Room/DataStore activity recreation and a synthetic real-process restart can establish persisted-state recomputation; neither establishes physical geofence delivery. These #80 checks are acceptance requirements, not independent completion evidence. Actual geofence behavior remains separate; no phone checks are claimed here.
