# Phase 1 capture Security Pass (#20)

Scope: offices, permission setup, passive geofence capture and recovery (#16–19). This pass adds no collection. It is refreshed onto merged #19 source; its own final sign-off requires independent and exact-head hosted gates. Actual closed-UI transition delivery on a physical device remains an explicit #18/#19 integration gate.

## Data and reachable surfaces

| Surface | Reviewed behavior |
| --- | --- |
| New local data | Office coordinates, radius and grace; immutable geofence transition IDs/times and receipt metadata in Room. App-private `capture_coverage` holds unknown/reviewed policy-local dates, health timestamps and registration confidence; `capture_health` holds a sanitized delivery-failure bit. No continuous track or location-coordinate sample is stored. |
| Permissions | Fine/coarse and background location support OS geofences; `RECEIVE_BOOT_COMPLETED` supports bounded re-registration. The packaged manifest has no INTERNET permission or other new dangerous permission. Denial, revocation and device-location-off keep guidance conservative and do not fabricate attendance. |
| Components and IPC | The Play Services callback is an explicit, non-exported, filter-free `GeofenceTransitionReceiver`. Its package-owned broadcast PendingIntent is mutable on Android S+ only because Play Services supplies transition extras. The exported `CaptureRecoveryReceiver` accepts only protected boot/package-replaced broadcasts. The launcher is exported; AndroidX ProfileInstaller's exported receiver requires `DUMP`. No exported/grantable provider or custom data endpoint. |
| Network, secrets, artifacts | No app network permission/client, backend, analytics, credential or production signing key. Tracked binary images are launcher assets and synthetic UI evidence. No tracked attendance database, log, key or personal location fixture. The preview APK uses debug signing; unsigned release inspection does not imply a publishable signed artifact. |
| Backups and exports | `allowBackup=false`, both cloud and device-transfer exclusions cover root, database, file, preferences and external domains. There is no attendance export or shared-storage writer. |

## Trust boundaries and regressions

The geofence callback is not reachable as an exported component. Inside the app it still rejects an absent/unexpected action, Play Services error, unsupported transition, missing/blank/overlong office ID and oversized batch before persisting. A new bound rejects more than 100 triggering offices, matching the registration limit. Repository insertion rejects unknown offices atomically; identical delivery replay is idempotent. A delayed event for a disabled but known office remains a source fact without earning current credit. The receiver never logs payloads, office IDs, coordinates or exception details; failure records a sanitized bit and an unknown coverage gap. A failed fence removal remains `FAILED`, not falsely healthy. Recovery after restart/boot/update re-registers before claiming platform health, and requires a subsequent real observation before confirming present-day office state.

The platform exceptions were checked against Google's [GeofencingClient](https://developers.google.com/android/reference/com/google/android/gms/location/GeofencingClient) documentation for Android S+ mutable PendingIntents and Android's [protected broadcast constants](https://developer.android.com/reference/android/content/Intent) for boot and own-package replacement. Mutability is limited by the explicit receiver/package target, and boot/update intents trigger re-registration rather than accepting attendance facts.

Focused Android tests cover two-office replay/unknown-office rollback, missing/future location time, malformed/oversized IDs, package-owned mutable PendingIntent and app-private coverage/health files. The private-file test checks actual paths/modes and requires shell UID 2000 to receive permission denial and empty output. Existing permission tests cover denial, approximate foreground, revocation and location-off; recovery host probes cover actual reboot/package update and setup changes. No real coordinates, attendance or credentials are used in tests.

`scripts/security_check.py` audits merged debug/release manifests, exact protected exported receiver actions, non-exported/filter-free geofence receiver, permissions, backup resources, direct location collection calls, runtime logging and forbidden bundled references. Adversarial Python tests mutate manifest/source inputs to prove these checks fail, including the new receiver and direct-location cases. The tracked synthetic dashboard screenshot was inspected; it shows no real location or attendance. Source/asset inventory found no tracked database, secret, credential or sensitive log. CI runs OSV against resolved runtime dependencies, Gitleaks and CodeQL at the PR head. Native `osv-scanner` and `gitleaks` executables are not locally available, so only hosted results can establish those scanner gates.

The exact source SHA, build checks, packaged debug/release permission and component inspection, APK checksum/signing caveat, hosted scanner results, independent verification and review belong to PR #69's evidence. No physical closed-UI geofence transition or manufacturer battery behavior is claimed here. This Security Pass remains open until its exact-head gates complete; #18/#19 remain open for real background-delivery evidence.
