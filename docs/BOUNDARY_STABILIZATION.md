# Office boundary stabilization (#100)

The engine derives attendance from immutable local observations ordered by observation time. It keeps every source ID in the resulting session audit and never rewrites a raw ENTER, EXIT, PRESENCE or ABSENCE. Delivery order and receipt delay do not decide visit order. App-private event evidence retains the source and available observation/receipt times; normal History copy describes office-area observations without showing raw IDs or claiming building entry or exit.

For one office, an EXIT followed by ENTER or PRESENCE within **60 seconds** is treated as a boundary bounce when a visit was already open and no other-office observation occurred between them. The derived visit keeps its original opening and arrival grace. Both observations remain attached to it; the apparent gap earns no second grace window or separate ordinary visit. This is a conservative fixed stabilization window for obvious immediate reversals, not a claim that the person was continuously inside a building. A later return, intervening other-office evidence, or an explicit recovery fix remains a distinct visit. The existing short-gap credit policy never bridges a gap containing other-office evidence or an explicit recovery fix, and never fills the new arrival grace.

Repeated ENTER observations and same-office observations already judged to be routine corroboration do not restart an open visit or create a blocking review. Foreground and periodic background reconciliation append a new PRESENCE only when their capture gate cannot safely treat the old open visit as continuous. Their persisted sources mark those observations for the engine to split the old span as `UNCONFIRMED_GAP`, leave that span uncredited and reviewable, and begin a new fix-time visit. An explicit recovery PRESENCE also takes priority over the 60-second bounce rule after an EXIT. The app passes this recovery marker from persisted event source metadata into the framework-free engine; it is not a mutable attendance fact.

After a visit's EXIT or a decisive outside check, another same-office EXIT with no intervening inside observation is redundant outside evidence only while an unobserved return could not have earned credit: its observation time must be within the larger of that office's arrival grace and the 60-second transient window of the latest same-office outside observation. A return hidden inside that bound would end before arrival grace expires or within the transient window, so it earns no credit under the ordinary rules. Observation timestamps are compared, not delivery times; when the platform supplies no fix time the receipt time is used, which can only overstate the gap and therefore errs toward review. A later EXIT outside the bound, including one hours later or on another day, remains a `MISSING_ENTER` orphan so the possibly missed arrival stays reviewable and the earlier visit is not relabelled. It remains an immutable raw fact and is attached to the preceding visit's source IDs, but does not create an orphan visit, a new departure time, or a second arrival grace. If the latest redundant EXIT is the only unconfirmed candidate, the preceding geofence EXIT remains unresolved rather than silently becoming confident. An EXIT before any credible inside observation remains an orphan for review. This rule is office-specific; it does not swallow a different office's evidence. A later ENTER or PRESENCE starts a new visit under the ordinary boundary rules.

An ENTER followed by EXIT within 60 seconds with no continuing earlier visit is one `TRANSIENT_BOUNDARY` review, not a confident departure. It earns no automatic credit; the original evidence remains for an explicit correction. A lone final EXIT beyond the window still ends the derived visit at its observed time. Bounded confirmation (#101) and weekday reconciliation (#89) handle that remaining false-final-exit risk. No continuous location service, exact alarm, upload or new permission is added here.
