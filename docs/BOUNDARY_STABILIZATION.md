# Office boundary stabilization (#100)

The engine derives attendance from immutable local observations ordered by observation time. It keeps every source ID in the resulting session audit and never rewrites a raw ENTER, EXIT, PRESENCE or ABSENCE. Delivery order and receipt delay do not decide visit order. App-private event evidence retains the source and available observation/receipt times; normal History copy describes office-area observations without showing raw IDs or claiming building entry or exit.

For one office, an EXIT followed by ENTER or PRESENCE within **60 seconds** is treated as a boundary bounce when a visit was already open. The derived visit keeps its original opening and arrival grace. Both observations remain attached to it; the apparent gap earns no second grace window or separate ordinary visit. This is a conservative fixed stabilization window for obvious immediate reversals, not a claim that the person was continuously inside a building. A later return beyond 60 seconds remains a distinct visit; the existing short-gap credit policy applies separately and never fills the new arrival grace.

Repeated ENTER observations and routine same-office PRESENCE observations corroborate an open visit without restarting it or creating a blocking review. A user-triggered foreground recovery PRESENCE is different: the capture gate appends one only when an earlier open visit cannot safely prove continuity. Its persisted source marks that observation for the engine to split the old span as `UNCONFIRMED_GAP`, leave that span uncredited and reviewable, and begin a new fix-time visit. The app passes this recovery marker from persisted event source metadata into the framework-free engine; it is not a mutable attendance fact.

An ENTER followed by EXIT within 60 seconds with no continuing earlier visit is one `TRANSIENT_BOUNDARY` review, not a confident departure. It earns no automatic credit; the original evidence remains for an explicit correction. A lone final EXIT beyond the window still ends the derived visit at its observed time. Bounded confirmation (#101) and weekday reconciliation (#89) handle that remaining false-final-exit risk. No continuous location service, exact alarm, upload or new permission is added here.

The synthetic 2026-09-25 regression uses the reported 09:39–12:45:30 sequence exactly. Its 11:01:29/11:01:41 and 12:06:12/12:06:27 flips remain attached to the original visit. The longer 12:06:52–12:43:05 gap remains separate because this issue has no evidence to declare it continuous. Tests also cover redundant observations, immediate and sustained departure, delivery reordering, arrival grace, foreground recovery split, correction aliasing, and multi-office interval union. Physical stationary-boundary and real leave/return evidence is still required for issue closure.
