# Android ingestion and persistence decisions

Verified against official Android / Google Play services documentation on 2026-09-23.

- [Android geofencing](https://developer.android.com/develop/sensors-and-location/location/geofencing): precise plus background permission, explicit mutable PendingIntent on Android 12+, at most 100 zones. Default radius is 150 m. Registration and recovery use the system geofencing service; no continuous position polling or foreground location service.
- [Background permission](https://developer.android.com/develop/sensors-and-location/location/permissions/background): request foreground access first; on Android 11+ background approval happens through settings. Manual history remains available if declined.
- [Broadcast handling](https://developer.android.com/develop/background-work/background-tasks/broadcasts): receiver uses `goAsync`, IO dispatch, an eight-second bound, and always finishes. It writes facts before completing. Durable WorkManager handles re-registration after boot, app replacement, or provider changes.
- [GeofencingEvent](https://developers.google.com/android/reference/com/google/android/gms/location/GeofencingEvent): the API provides a triggering location, not an exact transition timestamp. We retain its fix time as separate provenance, without retaining the coordinates. The domain receives receipt time as a conservative observed bound. Initial ENTER may mean already inside at registration; timestamps must be described as observed, approximate, and correctable.

Room stores offices, immutable event/correction records, exclusions, and WFH labels in private storage. Office revisions preserve creation/update timestamps and increment a version. Policy and capture-health metadata live in private DataStore. There is no destructive migration fallback; future schema changes require explicit migration. Generated v1 schema must be checked in once the Android build generates it.

Raw events have stable generated IDs and source tags. Manual sessions are stored as independent interval facts with notes, never as synthetic events mixed into the automatic transition stream. Repeating a manual-session or correction ID fails instead of overwriting evidence. WFH is distinct from exclusions. History deletion requires exact `DELETE` confirmation in the repository and a UI confirmation; offices and policy remain configured. Newly arriving automatic events after deletion can begin a new history. An explicit whole-day review can acknowledge unknown coverage for that date; reviewing a historical date leaves the intervening unobserved dates unknown.

Registration failure, missing permissions, unavailable providers, and Play services absence have explicit diagnostic states. Dates of detected monitoring gaps are kept unknown. Successful registration starts capture coverage; installation alone does not. Manually adding one old interval does not invent zero attendance on the surrounding historical days. A failed receiver write leaves a private diagnostic flag and marks the affected date unknown when next opened. We cannot retrospectively prove every unnoticed OS/force-stop/offline gap; minute accuracy and unattended reliability require physical-device acceptance testing. Google Play services' network location may require device connectivity even though the app itself has no Internet permission; local calculations and manual capture work offline.

Security review: both receivers are nonexported; the geofence PendingIntent names its component and is mutable only because Play services must populate its extras. No coordinates, provider payloads, or exception contents are logged. No network stack, external-storage export, secrets, or sync credentials are introduced. General cloud and device-transfer backup are disabled separately in the application manifest and XML rules.

Device acceptance: grant precise then background location; save two zones; cross each while screen off; verify receipt timestamps; deny permissions and disable providers; restore; reboot; force-stop and reopen; disable/edit a zone; verify a correction leaves raw evidence unchanged; confirm history deletion and cold restart. Emulator-only tests cannot establish OEM background reliability.
